## 0. 工作约定

- 日常功能修改不再自动打包 APK 或 Windows 安装程序。
- 当前版本固定为 1.0.0；未经用户再次指定，不自动递增或改用其它版本号。
- 仅在用户明确要求、到达可交付检查点、或准备发布前，才运行完整打包和安装验证。
- 每次实现仍做与改动直接相关的核心检查，避免断链；不为普通改动重复做全量验收。
- 本文中的状态含义：**已定**是用户明确确认；**已实现**是代码已有行为；**待定**不能据此自行设计或上线；**建议**仅供讨论，不是需求。

## 1. 已定的产品底线

### 产品目标

- 北极星：用户看到一道题，能想到可用解法，并知道这一招还可用在哪些题上；解法本身是副产品。
- 它不是搜题或单纯解题工具，而是帮助大一学生把高数题归类、联网、避坑的工具。
- 问答是主战场；练习和足迹为辅助。

### 体验与边界

- 纯前端、本地优先：WASM SQLite（sql.js）+ IndexedDB；不做账号、云同步、主动推送、底部标签栏、百分比、勋章或红点。
- LLM 直连；安卓通过原生 HTTP 处理 CORS。用户 API Key 仅本机保存，不能随 APK/安装包打入。
- 问答主界面只保留对话流和输入框；分类、拆解与画像更新均异步进行，不能卡住答疑。
- AI 在问答前台只自然回答题目，不强制输出分类标签、固定定性句或学习画像。
- 视觉采用暖白/纯黑灰阶主题；选中态用字重和细线；毛玻璃限抽屉遮罩与输入框；KaTeX 渲染公式。

### 会话与输入

- 一道题对应一个独立会话，由用户通过顶部“＋”或抽屉“新对话”主动创建；可在会话中持续追问。
- 程序重新打开落入新的空主会话；旧会话可从抽屉找回。
- 首条内容只触发一次快速 AI 短标题；用户手动改名后不允许迟到的 AI 覆盖。
- 图片上传不再出现“查看/确认题面”弹窗：用户发送后直接问答；模型在同次回答中识别题面时，识别文本自动贴在图片下方。
- 附件入口支持图片、文本、Word、PDF；附件面板应先收起键盘，再提供最近图片、拍照、相册、文件。
- 历史会话支持置顶、重命名、删除；删除时用户可选择只删聊天，或同时移除该聊天独有的学习记录。

### 分类、足迹与掌握度

- 现有分类骨架是基础，不要求重做：板块 → 情景组 → 情景 → 方法。
- 足迹只展示用户碰过的树；方法叶子是跳转而非展开，不能显示假箭头。
- 足迹展开与滚动是全局临时阅读状态，不绑定会话；进入新主会话时重置，进出方法页和切换已有会话时保持。
- 方法页展示适用情景；宽方法满足现有门槛时展示完整反向链接范围。反向检验练习已废弃，不应恢复。
- 对外掌握度为“刚碰过 / 巩固中 / 已掌握”，仅灰度区分。识别升级需要 3 次成功且覆盖 3 种结构面；执行升级需要 2 次成功且覆盖 2 道实际题。揭示答案不扣分，但不计独立成功。

### 练习的现有规则

- 处方只放练习页。早期“一条边三题”限制已由用户同意取消，改为围绕共同训练目标判断完整路线；允许综合题、一题多解和中间产生新情景。
- 基础层选一条可行完整路线；巩固层辨认给出的全部可行路线；高阶比较路线或写关键转折。具体结果不等同于会实际执行方法。
- 用户已明确：开始练习时训练点已确定，应优先从本地已经准备好、可追溯的题中筛选，而不是每次都等待即时生成。

## 2. 已实现、可直接使用的功能

- 首启、设置、问答、抽屉历史、练习、足迹、方法页、SQLite 本地保存、导入导出、Android 与 Windows 包装均已完成。
- 正常问答和方法讨论均支持 SSE 流式输出、检查点 Markdown 渲染、GFM 与 KaTeX；未完成的公式或 Markdown 不会提前破碎渲染。
- 方法页右下角有覆盖式聊天浮窗。它带入当前方法、适用前提及关联情景资料，不挤压原页面，不自动计入掌握度。
- 方法页“碰过的题”优先用短标题，题面仍可完整打开；解决长题面撑大按钮的问题。
- 抽屉可搜索会话标题、消息正文和本地提取的文件文本。
- 设置可选浅色、深色和跟随系统；用户偏好持久保存。
- 标题和后台归类使用独立的辅助模型请求，并尽可能按服务商/模型关闭思考；普通答疑保留用户的答疑模型与模式。Kimi K3/K2.7 等不能关闭思考的模型会改用可关闭的辅助模型或保留用户显式配置。

已实现行为、接口字段依据和验证范围详见 [会话与足迹交互更新](会话与足迹交互更新.md)。M0～M9 历史实施与验收记录见 [实施记录](实施记录.md)、[验收清单](验收清单.md)。

## 3. 用户已经确认、但尚未实施的第二版方向

### 3.1 经典母题与本地题库

- 围绕**现有情景**筛选高数经典母题；由用户最终把关哪些题入库。
- 每道母题必须有明确训练目标、关联条件、可控变化方向、正确题面与正确答案依据。
- 母题是可复用实体：可关联多个情景和方法，但必须记录“哪个方法在题目的哪个环节、为什么适用”，不能把所有标签任意交叉配对。
- 少量非常经典的母题可保留原题；其余一部分题目将来由 AI 生成受约束的变式。约 20%～30% 是早期方向，统计口径与最终比例尚未确认。
- 变式应借鉴“题根 → 受控变化 → 类比拓展”的思路，不能只改数字，也不能脱离原题训练目标。

### 3.2 方法与情景内容

- 方法页将补充适用范围、定义和原理：基于教材可靠内容，再做简洁、像人话的转述；没有独立正式定义的技巧不能编造教材定义。
- 情景和分组术语也需要解释。用户应能理解“未定式”等名称的定义、特征、识别信号、例子与相近概念的边界。
- 方法页中“这招还能用在这些地方”的情景必须可点击，进入相应情景详情；不能只显示不可用的灰色文本。

### 3.3 练习与等待

- 当前练习题的内核、选项和反馈过于单调；不能让用户只凭当前主题就猜到正确选项。
- 练习应让用户阅读具体条件、判断适用方法或关键操作；题面变化需要有数学训练价值。
- 做题历史需要有清晰、容易发现的集中入口，能回看题面、个人作答、反馈和参考依据。
- 拍照后需要增加可选裁切，便于从多题照片中选出本次题面；不能借此恢复旧的 OCR 确认弹窗。

## 4. 仍待集中决策的事项

### A. 母题库：下一轮讨论的首要问题

1. **首批覆盖范围**：从哪些现有板块、情景和方法开始；每个单元先收多少候选题与最终母题。
2. **来源与版权处理**：哪些教材/教辅、版本和来源可作为候选；原题在本地保存、展示与未来发布时分别保留到什么粒度。
3. **入库标准**：怎样判定“经典、典型、值得做题根”；同一结构的近似题保留几道；什么题应拒绝。
4. **核对责任与流程**：题面、答案、定理前提、图形与公式如何校验；用户把关、人工核对、模型辅助各做什么；什么状态才可进入本地练习池。
5. **字段最小集与工作流**：下节给出草案，需确定哪些字段首批必须填，哪些可以以后补。
6. **变式边界与质量控制**：哪些结构必须不变、哪些条件可变、何时仍属于同一训练目标；生成后怎么验题、验解、验分类。
7. **AI 题比例与调用策略**：20%～30% 的具体口径；本地题不足时是给相近题、提示缺题，还是在线生成；是否预生成、何时触发、费用由谁控制。

### B. 练习的作答与反馈

1. 默认交互仍是多选方法、写步骤，还是改成其他形式；它们在一轮题组中怎样配合。
2. 题组是否一直“一条边三题”，还是允许在后期加入有明确目的的混合题组。
3. 选项应该呈现方法名、关键操作、完整方案比较，还是组合形式；哪些干扰项算合理。
4. 对“写几步”如何批改，什么表现可计为识别/执行成功。
5. 历史入口放在练习页、足迹页，还是共用入口；重做、删除、修订题目时怎样避免重复累计掌握度。

### C. 情景详情与方法内容

1. 情景详情的确切层级和入口：板块、情景组、叶子情景分别写什么；长按、显式按钮、桌面交互怎样统一。
2. 方法详情的内容模板、默认篇幅、教材版本、原文出处与通俗转述的保存方式。
3. 方法讨论浮窗已经可用，但其正式内容上下文要等教材依据与情景详情内容建立后再升级。
4. 方法 → 情景详情的导航、返回与探索范围如何表现；未接触情景是否照常允许探索，以及如何表达可点击性。

### D. 输入与问答的后续改进

1. 图片裁切的入口、是否覆盖相册和文件、裁切框/旋转/原图保留策略。
2. 主问答的教学过程怎样更好地促成“想到方法”，而不把主界面重新塞入标签、卡片或固定讲座。
3. 真实服务商的等待、数学质量和不同模型表现需要以后用可控样本测量；目前的技术验证不等于数学教学质量验证。

## 5. 母题信息的当前推荐草案（未定案）

| 信息组 | 建议内容 |
| --- | --- |
| 身份与来源 | 稳定编号、教材/教辅、版本、章节、页码题号、原文位置 |
| 原题与条件 | 完整题面、公式、图形、变量范围与全部条件 |
| 训练目标 | 具体能力，以及它为什么值得成为母题 |
| 分类关联 | 主情景、其他情景、核心方法、有效替代方法及各自适用环节 |
| 识别线索 | 触发该情景的条件、关键转折和易错边界 |
| 答案依据 | 答案、可核对解答、定理及前提、来源和校对记录 |
| 变式规则 | 不变量、允许变化、禁止变化、预期训练变化 |
| 题组属性 | 前置知识、难度、运算负担、独立练习/综合拓展用途 |
| 状态与版本 | 待整理、待核对、待用户确认、可用等状态；变式追溯关系 |

推荐的最小流转为：候选题 → 完整整理 → 数学核对 → 用户选定母题 → 建立变式规则 → 放入本地练习池。这个流程和字段是建议，不是已决定的后台设计。

## 6. 已明确不做或暂不恢复的内容

- 账号、云同步、底部标签栏、主动推送、百分比、勋章、红点、重型状态/组件库。
- 前台常驻分类标签、答后“注意这些坑/还能用在哪/换马甲”等折叠条、欢迎页、题面确认弹窗。
- 独立“反向检验”练习；它不符合用户在实际解题过程中的判断时机。
- 未经讨论就自动大规模采题、预生成题目、联网调用模型，或把模型生成题直接视为经典题。

## 8. 建议的本次讨论顺序

先把母题库讲清楚：用少量真实候选题，逐道判断是否入库、落在哪个情景/方法、填写哪些必填信息、允许哪些变式。这样才能给本地供题、练习重设计、AI 变式和方法/情景内容提供可靠材料。

母题样本稳定后，再确定练习作答机制与历史入口，最后确定情景详情、教材内容模板和图片裁切的交互细节。
