# 可靠性与学习衔接修复

本轮在现有 3.9.0 源码上修复，不修改应用版本、不生成安装包，也不提交或上传 Git。所有验证使用内存数据库或隔离浏览器中的虚构数据，没有打开用户学习库或调用付费模型。

## 用户能感受到的变化

- 收藏题详情增加“查看原解答”，定位到原始用户气泡。较早的消息会进入渲染窗口；题目编辑过时切回对应历史版本。原对话删除后仍保留收藏题面，并明确说明来源不可用。
- 已接触的情景详情增加“练这个情景”；方法详情增加“练相关情景”。进入现有练习入口并选好对应目标，保留正在做的题组，用户点击“开练”后才开始。没有合适入口时显示实际状态，不跳到无关目标。
- 本地练习正确取回选中题池的完整数据，再发送到数据库 Worker，修复入口摘要缺少题目数组导致无法开练的问题。

## 数据与恢复

- SQLite 数据版本由 9 升为 10。新增 `classification_result` 保存每条回答的归位结果、原用户消息锚点及路径依据。它与执行队列分开保存，终态任务清理不再删除学习记录，也不再让这些答案自动重复分类。
- 迁移保留旧任务中已有的路径。若旧任务早已删除但仍有接触记录，则恢复为无序关联，不推测不存在的先后顺序。旧版已删除且没有留下任何证据的信息无法还原。
- 失败的归位结果在清理后仍可展示并由用户重试；重建任务只针对被明确请求的回答。
- 自动清理仅删除超过 14 天且未被消息、附件或收藏引用的孤立图片。正文非空不再被当作“题图可删”的依据。
- 备份保留全部题图及其引用，继续从导出副本中去除 API Key；支持时仅对副本中的图片压缩，不改变本机原图。
- 导入时将本机有效模型配置与导入数据放在同一次持久提交中，避免界面看似保留配置、重启后却丢失。
- 保存失败时合并失败批次与新到内容的脏消息集合，保留原题和最新推导。落盘前同步尚未执行动画帧中的文本与思考内容。
- 重启后根据已保存的状态恢复部分回答的“继续”入口。应用退出与用户主动停止分别记录；不自动重启用户主动停止的回答。
- 后台任务在加载知识库期间被前台操作打断时释放已认领任务，保留重试机会。

## 性能范围

历史侧栏订阅稳定的会话摘要。回答正文和思考内容逐帧变化时，不再触发整份历史的排序及条目动画扫描。归位归档只处理缺失或状态变化的记录，避免启动时重复改写已经归档的结果。

本轮没有重构 SQL.js 的整库快照持久化，也没有将已加载会话的全部图片迁到独立文件存储。大量图片下的快照体积、长期内存占用，以及首次进入练习时的大题库加载仍需单独测量和优化，不能视为已经解决。

## 验证

- 全量 Node 回归测试及生产网页构建，输出保存在忽略目录 `.qa/reliability-verified-tests.log` 和 `.qa/reliability-verified-build.log`。
- 新增真实 SQL.js 回归覆盖任务清理与连续重启、v9 迁移、归档失败任务重试、导入提交失败后重试和立即重启、部分回答恢复。
- 保存层覆盖写入等待期间再收到新内容并失败，以及动画帧未执行时的思考内容保存。
- 浏览器使用虚构的 16 轮长会话：收藏跳回第 1 题，手机宽度下目标距内容区顶部 16px；情景详情进入对应练习并实际打开本地题目。浏览器未报告运行错误，验证结束后已关闭浏览器和临时服务器。
- 构建仍提示题库分块超过 500kB；构建成功，本轮没有为消除提示而更改题库内容。
