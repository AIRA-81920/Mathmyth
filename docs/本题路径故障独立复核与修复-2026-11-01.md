# 本题路径故障：独立复核与修复

2026-11-01。先复核工作区与原始材料，再编写失败用例，最后修改生产代码。保留了接手时已有的未提交诊断改动。

## 结论与证据边界

**手机截图证明的直接故障是：后台已领取任务、模型已返回，但归位校验抛错，整份结果未被接纳。** 并非所有任务都不执行：同一截图同时有 `pump:completed`。

两条能对应到真实数据库的失败记录：

| 答案 / 任务 ID 后缀 | 手机截图记录 | 对应修复前代码 |
| --- | --- | --- |
| `message-33c3d538-0f3d-4dbc-8739-6f341a2e9cfa` | 22:59:54.490 缺少解答依据；23:00:12.116 连线重复 | `questionRoutes.js` 原第 19–20 行同时校验配对和逐字摘录；`locate.js` 原第 42 行遇到重复直接 throw |
| `message-ad1aa077-e1e7-4f10-b259-c572ec8f8779` | 22:59:32.538、22:59:46.085 连线超出骨架；23:00:03.878 连线重复 | `locate.js` 原第 38–42 行：配对校验、重复校验 |

截图里没有模型原文，因此**不能确定当时重复的是哪一条配对，也不能把“缺少依据”一律解释为标点或换行差异**：原错误分支还包括路径配对不存在。已补失败原文捕获和结构化定位字段，后续可直接查 `entryIndex`、`routeIndex/pathIndex/stepIndex`、`edgePresent`、`evidenceMatched`。

这次没有调用真实模型服务，也没有读取桌面配置中的密钥。不能宣称已完成手机同配置的端到端复测，更不能证明为何某个旧版本在用户当时的使用中成功、新版本失败。

## 项目结构

- React 页面与 Zustand 维护问答、练习、足迹等前台状态。问答完成后，持久化层将完整公开解答存入数据库并入队。
- `runner.js` 在前台空闲时领取任务，经 `locateBlocks → checkpointJob → locateEdges → completeJob` 整理路径；前台问答/练习抢占模型时让出。
- SQLite 在 Worker 内运行，IndexedDB 保存快照。`classification_result` 保存学习结果，`queue_job` 保存执行状态与租约。路径按具体答案展示。
- Electron 与 Capacitor 使用同一套业务代码，模型传输层适配网页与原生请求。

## 原始材料复核

数据库：`buggg/Mathmyth-2026-10-31 (1).sqlite`，2,781,184 字节，SHA-256：

`6ab59db0469022b92cc554b9c973d76cbb272c387594d0dda2f3d070c4b4bc16`

只读统计结果：schema 12；25 个会话、252 条消息；25 个 pending、1 个 done、没有 failed 队列行；63 条分类记录，其中 done 53、failed 10；25 个 pending 均符合领取 SQL。备份没有 API Key。

两张手机截图显示的是**另一个时点**：pending 21、failed 1、done 5。不能把它当成该备份的队列表统计。截图最近一次 pump 在设置页退出，`usable=false`；之前在主页面执行时 `usable=true`。

另外，`archiveClassification()` 将 `job.created_at` 写进分类记录；这个值来自原答案时间，**不是归位执行完成时间**。例如截图 23:00:20 成功的 `message-e7ed3fc3…`，在数据库中的创建时间为 10 月 16 日。因此不能凭分类记录日期断言“10 月 16 日后归位没有成功过”。交接的 `analyze-export.mjs` 还查询了不存在的 `updated_at`，那一项输出不构成证据。

复跑命令，工作目录均为 `frontend`：

```powershell

node .qa/verify-route-backup.mjs '../buggg/Mathmyth-2026-10-31 (1).sqlite'

```

## 对交接五条排除项的复核

| 排除项 | 结论 | 理由 |
| --- | --- | --- |
| 不是队列没跑 | 对截图所处时段同意；对所有使用时段无法验证 | 截图有领取、检查点、成功与失败。备份里的 pending/attempts=0 本身不能证明从未运行，claim 仍是非持久提交。 |
| 不是版本间代码改动 | 不同意作全面排除 | 从 3.1.0、4.2.0、4.2.1 APK 用 AST 提取实际校验函数，执行相同样本：三版都接受有效连线、拒绝重复、拒绝换行差异、拒绝路径别名不一致。这只证明这些分支在这些样本上一致，不证明整个运行链等价。 |
| 不是骨架改名 | 对历史成功样本同意；对当前全部失败无法验证 | 95 个历史步骤在当前骨架均存在且配对有效，不覆盖截图里未保存的非法返回。 |
| 关思考不是本版引入 | 对规则存在性同意；质量影响无法验证 | 四版 APK 都含官方 DeepSeek 的 disabled 规则。不据此推断模型质量无变化，也未修改该规则。 |
| 换模型导致 | 不能认定 | 用户明确报告两家配置都出现问题；现有材料无法建立换模型与故障的因果关系。 |

交接的旧重放脚本还截取了题面/回答，并重新组装 source；`measure-edges.mjs` 使用 `ping` 系统提示词。它们可以测试各自请求，但不能证明与手机失败请求输入完全相同。

## 已实现的修复、代价与风险

| 改动 | 为什么能修复 | 代价 / 边界 |
| --- | --- | --- |
| 相同正式情景/方法配对去重，合并其主线标记 | 重复出现不再导致整题丢弃；别名先归一 | 仍拒绝非法配对和多个不同主线；不删除路径内重复操作 |
| 路径方法别名与 encounters 同步归一 | 消除 encounters 接受 `M.taylor`、路径却因正式 ID 不同被拒绝的内部不一致 | 只接受骨架已有别名，不猜新 ID |
| 证据匹配支持空白与全角 ASCII 差异，再恢复公开解答中的原文 | 排版差异不再丢结果，存入数据库的 evidence 仍是逐字子串 | 不做 NFKC，不把 `x²` 改为 `x2`；不接受改写、错符号和缺失步骤 |
| 按完整的并列解法隔离证据失败 | 一种解法不合规时，另一种已完整验证的解法仍可返回 | 不截断连续步骤；所有解法无效仍失败；无法恢复没有返回的解法 |
| 领取后到结果准备完成设 45 秒总期限 | 持续思考帧不能无限续期；即使外部 Promise 不响应 abort，队列也能退出 | 慢模型会超时并消耗真实失败预算；45 秒是截止策略，不是实测速度承诺；不改前台回答时限，不中断已开始的数据库完成提交 |
| 当前会话最新回答优先，成功后立即接下一项 | 真实备份中最新题原本排第 25；新题无需先等其他会话积压 | 当前会话持续产生工作时，旧会话可能继续等待；旧任务保留 |
| 面板与重排统一为 2 分钟；允许重排陈旧 running；记录 requeuedAt | 修复“按钮已出现但 30 分钟内什么也不做”；旧 lease 作废；刚重排不再立即判卡住 | 不需要 schema 迁移；原答案时间保留；新排队时间写入任务 payload |
| 校验失败捕获脱敏的最多 4,000 字符返回和具体位置 | 下次失败可定位到一条模型数据，而非继续猜测 | 仅在本机诊断环形日志中保留；精确清除当前 Key 及常见密钥字段；不记录请求头/配置；原文可能被截断或覆盖 |

传输层原本已有 15 秒连接超时与 180 秒空闲超时。“完全没有请求超时”不准确；真正缺的是后台任务总期限。持续收到思考帧时，空闲超时会不断重置。

## 修复前失败 / 修复后通过的测试

原有基线 459/459，修复后全量 474/474；隔离 Vite 构建通过。新增 15 个用例位于 `tests/location-recovery.test.mjs`：

| 用例 | 修复前 | 修复后断言 |
| --- | --- | --- |
| 重复正式 ID / 别名配对 | 抛“连线重复” | 只存一条，主线保留 |
| 摘录仅空白/全角差异 | 抛“缺少依据” | 恢复逐字原文且是 answer 子串 |
| encounters 与路径同用合法别名 | 抛“缺少依据” | 两处均变为正式 ID |
| 一条并列解法含无依据中间步骤 | 整题失败 | 整条无效解法移除，另一完整解法保留 |
| 错误定位字段 | 无法区分配对与摘录错误 | 返回具体索引和匹配布尔值 |
| 多题、多解法的原始索引 | 逐解法检查会把索引归零 | 保留模型返回中的真实题目、解法、步骤索引 |
| 失败返回诊断 | 无原文 | 有上限、有位置，不含伪造测试 Key/密钥字段值 |
| 超过 2 分钟的 pending | retried=0 | retried=1，随后 stalled=false、不可立即反复重排 |
| 陈旧 running 重排 | retried=0 | retried=1，旧 lease 完成写入被拒绝 |
| 新会话有旧积压 | 先领旧会话 | 先领当前会话；同会话按最新回答优先 |
| 不响应 abort 的模型 Promise | 一直 running | 总期限后退回 pending、attempts=1，迟到结果不落库 |
| 每 5ms 返回真实思考 SSE 帧 | 空闲期限不断续期 | 总期限仍结束请求，按失败而非用户取消计数 |

另有保护用例：错误符号/上下标/改写仍拒绝，所有解法无依据仍失败。原有非法配对、租约失效、前台抢占、持久化和路径展示测试继续执行。完整日志在 `.qa/route-fix-all-tests.log`；隔离构建日志在 `.qa/route-fix-build.log`。

真实备份的内存验证：35 条带证据的历史成功记录、95 个步骤通过；最新题优先领取；25 个积压任务均走通领取、检查点与完成回写。**队列验证显式使用空结果模型桩，不代表真实模型已为这 25 道题生成正确路径。**
